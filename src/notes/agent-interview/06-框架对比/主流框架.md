# Agent 面试专题：框架对比 · 主流框架

> 校订：2026-09-21。面向高级工程师、架构与技术负责人。保留专题 Q 编号；与主题库 Q 编号分开使用。

## Q10: 如何比较当前 Agent 框架、SDK 与托管运行时？

### 专业版答案

按责任边界比较，而非给框架排能力榜。核对日期：2026-09-21。

| 方案 | 重点抽象 | 选型要核实 |
|---|---|---|
| LangChain / LangGraph | 高层 Agent / 可定制图与状态编排 | 持久化、状态合并、恢复及运维 |
| OpenAI Agents SDK | 应用内运行的 Agent、工具和 handoff | 自有部署、存储与工具集成 |
| OpenAI Agents API | 托管 harness 与长任务会话 | 数据边界、沙箱、资源生命周期和退出成本 |
| 直接使用模型 API | 自有循环和适配器 | 运行时能力需自行实现 |
| CrewAI | Crews 的角色任务协作与 Flows 的流程状态 | 流程控制、持久化和失败语义 |
| Microsoft Agent Framework | 微软体系 Agent 与工作流 | 目标语言、集成与迁移契约 |
| 既有 AutoGen 系统 | 存量协作系统维护 | 维护状态和迁移成本 |

AutoGen 官方仓库已标注维护模式，并建议新用户考虑 Microsoft Agent Framework。AutoGPT 可作为产品/历史案例，不再用“长期任务就换 AutoGPT”作为默认选型规则。

依据：[LangChain v1](https://docs.langchain.com/oss/python/migrate/langchain-v1)、[OpenAI 运行时对比](https://developers.openai.com/api/docs/guides/agents)、[AutoGen 仓库](https://github.com/microsoft/autogen)、[CrewAI Flows](https://docs.crewai.com/en/concepts/flows)。

### 白话版答案

先看谁管执行、状态、权限和运维，再看写 demo 是否方便。

### 高级追问与评分点

给两个候选方案设计两周验证，要求包含重启恢复、审批撤销、跨租户隔离、成本与退出测试。

## Q11: 如何选择 Agent 框架？选择标准是什么？

### 专业版答案

先写需求矩阵：任务长度、流量、工具风险、人工等待、隔离、语言、数据部署边界、团队经验和维护预算。再做最小 PoC，跑同一组任务与故障注入。

至少比较成功率、每成功任务成本、P95、恢复语义、可观测性、测试替身能力、供应商替换难度及维护状态。避免仅比较 GitHub 热度、几行代码或角色数量。

业务领域模型和工具契约尽量独立于框架；只对实际需要替换的边界做适配，不要提前设计吞并所有差异的万能抽象。保留明确的退出条件与迁移工期。

### 白话版答案

让框架通过你业务的真实考试，再决定使用。

### 高级追问与评分点

团队已经熟悉一个框架，新框架评测略优，迁移收益如何覆盖稳定性、培训和维护成本？
