# Agent 面试专题：记忆系统 · 记忆压缩与遗忘

> 校订：2026-09-21。面向高级工程师、架构与技术负责人。保留专题 Q 编号；与主题库 Q 编号分开使用。

## Q59: 记忆遗忘机制 (Memory Forgetting) 是如何实现的？

### 专业版答案

遗忘包括上下文淘汰、业务过期和隐私删除，三者不同。上下文淘汰只影响本轮输入；TTL 使旧事实不再可读；隐私删除需要覆盖原文、索引、缓存和派生产物，并按明确保留策略管理日志与备份。

时间衰减与重要性评分可用于排序，但不能随机删除法律保留记录或仍需履行的业务承诺。删除采用墓碑、事件传播和读取拦截，恢复备份时也要重放删除状态，避免“复活”。

### 白话版答案

不放到眼前、标记过期和真正删除，是三件事。

### 高级追问与评分点

给出可验证的删除完成标准，并说明哪些数据因保留政策无法立即物理清除。

## Q60: 实体记忆 (Entity Memory) 在 Agent 中有什么用？

### 专业版答案

实体记忆把人、组织、订单等对象的属性和关系按稳定 ID 管理。实体解析需处理同名、别名、合并和拆分，不能仅靠文本相似度认定为同一人。

每个事实绑定实体 ID、来源、有效时间、租户和版本。重要业务值从权威系统读取，模型提取只作为候选。图数据库适合关系遍历；简单属性查询用关系库也可以，不能为“实体记忆”默认引入知识图谱。

### 白话版答案

先确认说的是哪一个人或订单，再记录它的事实。

### 高级追问与评分点

两家租户都有“张伟”，如何避免跨租户实体合并和检索泄露？

## Q61: 共享记忆 (Shared Memory) 在多 Agent 系统中如何工作？

### 专业版答案

多 Agent 共享记忆应暴露结构化事实和产物引用，区分临时发现、已验证事实与执行命令。读写按任务和租户隔离，写入附来源、版本与责任主体。

并发更新采用单写者、乐观锁或事务；冲突时显式合并或人工处理。消息总线负责通知，不自动提供事实一致性。子 Agent 不能通过共享存储给其他 Agent 写入更高优先级指令或伪造完成状态。

共享越多不一定协作越好。先定义最小共享 contract，并限制广播和重复读取。

### 白话版答案

共用的是有来源、有版本的工作记录，不是所有人都能任意改的一段聊天。

### 高级追问与评分点

两个 Agent 分别断言任务成功和失败时，哪个状态生效？要求基于验收证据和状态权限决定。
