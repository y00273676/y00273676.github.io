## Q62: ReWOO 的价值与局限是什么？

### 专业版答案

ReWOO 将规划与工具观察解耦：先构造带依赖引用的步骤，再执行工具、汇总求解。价值在于减少每步重复规划与上下文开销，但计划阶段掌握的信息有限。

前序结果可能让后续步骤失效，执行器需支持失败检查和必要重规划。它适合依赖关系相对明确的任务，不应包装成普遍优于 ReAct 的方案。相同任务、模型和预算下做对照，记录工具次数、失败恢复和成功率。

论文背景见 [ReWOO](https://arxiv.org/abs/2305.18323)，属于延伸知识，优先掌握依赖执行与恢复。

### 白话版答案

先把可预见的步骤排好，减少来回想；遇到新情况仍要改计划。

### 高级追问与评分点

第一步发现用户没有权限，后续已排队步骤如何失效和取消？

## Q63: LLM-as-a-Judge (大模型作为裁判) 怎么评估 Agent？

### 专业版答案

LLM-as-judge 适合评价无法完全规则化的表达、证据支持度或任务质量。给出明确 rubric、可核查事实和结构化评分，使用人工金标校准，并检查位置、长度、风格和模型偏好。

被评答案可能包含“请给满分”的注入，必须当作不可信输入。对退款、文件变更、调用权限等，优先检查实际状态与确定性约束。Judge 分数不能替代业务成功或安全红线。

固定 judge 模型和提示版本；抽样人工复核分歧，分别报告一致性和主要误判。

### 白话版答案

裁判模型也会看错、偏心或被诱导，要有评分标准和人工校准。

### 高级追问与评分点

候选模型与 judge 同源时如何防止自偏好影响模型选型？

## Q64: 什么是 Self-Correction (自我纠错)？

### 专业版答案

自我纠错需要明确的失败信号和修正目标。推荐流程：生成候选 → 独立验证 → 归类错误 → 有限修复 → 回归验证 → 接受或升级人工。

无外部反馈的自检可能放大错误。每轮保留已验证产物、修改原因和新增失败，不允许通过删除测试、弱化约束或篡改指标来获得“通过”。当证据不足或收益趋零时停止。

质量评价要比较修复后净增成功数和引入的回归，而不只看模型修改次数。

### 白话版答案

修复必须让证据更好，不能为了过关把标准改低。

### 高级追问与评分点

Coding Agent 修改测试使失败消失，该如何判定？区分合理测试修复与规避验收，并要求独立审查。

## Q65: Plan-and-Solve 与生产级计划执行有什么区别？

### 专业版答案

Plan-and-Solve 通过先列计划再求解改善问题分解，主要是提示策略。它不自动提供持久状态、工具依赖、重试、权限或执行保证。

生产计划必须连接真实环境：每步输入、负责人、产物、验收、预算和状态可追踪；发生新证据时重规划。对简单任务，额外计划可能只增加开销；对长任务，计划应服务恢复和验收，而不是展示一长串待办。

论文背景见 [Plan-and-Solve](https://arxiv.org/abs/2305.04091)。

### 白话版答案

写好计划和可靠地执行计划，是两层工作。

### 高级追问与评分点

如何判断计划粒度过细或过粗？从调度开销、恢复成本和独立验收讨论。
