Q12: Agent 在客服场景如何应用？有哪些挑战？

专业版答案

客服适合意图理解、知识检索、订单查询和回复草稿。退款、改地址等写操作由业务服务验证资格、额度和身份，模型只提出动作。

系统设计包括用户会话、权限感知检索、订单工具、审批与操作账本、人工接管。用户问题不清时澄清；工具失败时说明已确认的状态，避免“安抚性虚构成功”。

评测同时看问题解决率、错误操作、转人工质量、处理时长和复联率；降低转人工率并非唯一目标。客服策略变更需带版本并回归历史失败样本。

白话版答案

让它做好查询和沟通，把真正改订单的钱和权限管住。

高级追问与评分点

如何定义一次退款任务完成？模型回答、接口成功、账务到账分别是什么证据？

Q13: Agent 在数据分析场景如何应用？

专业版答案

数据分析 Agent 应先绑定指标口径、数据权限和时间范围，再生成受限查询、执行、校验和解释。指标定义来自语义层或权威目录，不由模型即兴拼公式。

SQL 工具用只读角色、表列和行级权限、AST/受限 DSL、参数化、超时及扫描/结果限额；只检查 SELECT 前缀不安全，SELECT 也可能调用有副作用函数或泄露数据。租户 ID 来自服务端上下文。

输出附口径、查询/数据版本、刷新时间和证据。对账检查合计、重复、空值和时间边界；不能让漂亮图表掩盖错误口径。

白话版答案

先确定怎么算、能看哪些数据，再查和解释。

高级追问与评分点

报表同比异常，如何分辨数据刷新、时区、指标定义和模型解释四类问题？
