# Agent 面试专题：框架对比 · 框架深度解析

> 校订：2026-09-21。面向高级工程师、架构与技术负责人。保留专题 Q 编号；与主题库 Q 编号分开使用。

## Q66: LangChain 与 LangGraph 如何分工，而不是互相替代？

### 专业版答案

LangChain 提供高层 Agent 及集成，LangGraph 提供更细的状态与图编排能力；现代高层 Agent 可以构建在 LangGraph 之上。不能再用“LangChain 只能线性，LangGraph 才能做 Agent”概括二者。

需要控制分支、状态合并、人工暂停和恢复时，审视是否需要自定义图。使用 checkpointer 仍须确认落盘、thread 隔离和重放语义；store 与 checkpoint 负责不同数据范围。

依据：[v1 迁移指南](https://docs.langchain.com/oss/python/migrate/langchain-v1)、[Persistence](https://docs.langchain.com/oss/python/langgraph/persistence)。

### 白话版答案

一个提供常用成品结构，一个让你更细地控制运行流程。

### 高级追问与评分点

什么时候不用框架而写普通状态机更合适？从复杂度、团队掌握程度和验证成本回答。

## Q67: 旧版 GroupChatManager 题应如何转化为通用协作设计题？

### 专业版答案

把“谁当群聊主持人”转为四个问题：谁拥有目标状态、谁选择下一执行者、谁能调用有副作用工具、谁判定任务完成。

轮询、规则路由、模型选择和管理者委派各有成本。需防止两个 Agent 相互转交、重复工作和无限讨论；总预算、最大交接次数、进展证据和取消由可信协调器控制。

GroupChatManager 是版本相关的历史 API，通用考点是调度与状态责任。存量系统维护背景见 [[06-框架对比/AutoGen深度解析]]。

### 白话版答案

主持人最重要的工作是管任务、分工和结束，而不是让大家一直说话。

### 高级追问与评分点

两个专家结论矛盾时谁裁决？高分答案根据证据权威、验证器和升级策略处理，而不是简单多数投票。

## Q68: 角色 Prompt 能否代替专业能力、权限隔离和独立评审？

### 专业版答案

角色提示影响行为偏好，不能凭空增加领域知识，也不能隔离凭据或改变授权。多个相同模型可能共享错误；“专家投票”不自动提供统计独立性。

专业能力要靠任务数据、工具、训练/检索和评测证明。权限隔离由工具网关、运行环境和身份系统实现。独立评审依赖独立证据与验收标准，审查者不应只阅读生成者的自我总结。

可保留角色分工作为提示与组织手段，但必须验证它相对简单方案的增益。

### 白话版答案

给三个模型分别起专业名字，不等于真的有三个独立专家。

### 高级追问与评分点

如何设计真正能发现生成者错误的审查环节？要求原始证据、不可篡改测试与明确拒绝理由。

## Q69: 多模态 Agent (Vision) 落地的核心挑战是什么？

### 专业版答案

多模态落地要验证输入分辨率、裁剪、坐标映射、页面状态和证据来源。OCR、图表理解、视觉定位与动作执行是不同能力，需要分别评测。

Computer Use 应按“观察 → 定位 → 动作 → 再观察”闭环执行；页面切换后旧坐标不可信。优先使用适合任务的稳定 API 或语义定位，必要时才使用坐标动作。截图、网页文字和隐藏内容可能含间接注入。

限制网站、文件、账号和网络出口，写入前检查目标与参数，保留操作证据及恢复路径。本题保留旧编号，详见 [[05-多模态/核心概念]]。

### 白话版答案

看得懂屏幕不代表点得准，点完还要确认状态确实变了。

### 高级追问与评分点

屏幕显示“提交成功”但业务未落库，如何判定和恢复？

## Q70: 如何解决 Agent 的“幻觉” (Hallucination) 问题？

### 专业版答案

先分类：事实无证据、引用不支持结论、工具结果误读、过期数据、虚构执行成功。分别用带版本的检索证据、引用核验、结构化结果、权威系统查单和允许不确定回答处理。

RAG、低温度和自我反思都不能根除幻觉。工具调用成功也不代表业务目标完成，应检查真实后置状态。对于高风险输出，设置证据门槛、专业复核及可追责记录。

衡量覆盖率与正确率的关系，防止靠大量拒答把准确率做高；分别报告拒答、错误行动和成功完成。

### 白话版答案

说得有依据、做得有凭证，不确定时不能编造。

### 高级追问与评分点

引用文本存在但不支持结论，如何设计可自动检查与人工复核结合的评测？

## Q71: 如何选择和正确解释 Agent 评测基准？

### 专业版答案

选基准先匹配任务。SWE-bench 系列针对真实软件问题修复；τ-bench/τ²-bench 关注工具、用户交互和业务约束。不同版本、子集、环境、预算和评分器不能直接横比。

同时记录模型、harness、工具权限、尝试次数、执行预算、测试环境与污染风险。榜单成功率不等于企业线上成功率，应补充私有新样本、权限测试、恢复测试与人工审查。

pass@k 关注 k 次中至少一次成功；pass^k 关注 k 次都成功。前者还需要可靠候选选择机制，不能把多次试错当作免费且安全。

依据：[SWE-bench](https://www.swebench.com/)、[τ²-bench](https://github.com/sierra-research/tau2-bench)、[Agent evals](https://www.anthropic.com/engineering/demystifying-evals-for-ai-agents)。

### 白话版答案

看分数前先看考的什么、允许试几次，以及是谁判断成功。

### 高级追问与评分点

一个模型 pass@10 很高但单次成功率低，适合自动付款吗？解释重试副作用与稳定性要求。

## Q72: 如何回答“Agent 是否通向 AGI”，并落到可验证的技术路线？

### 专业版答案

Agent 描述目标导向的交互与执行系统；AGI 的定义和判定尚无统一工程验收标准。不能把“Agent 必然是 AGI 的中间阶段”当作事实。

负责人应把讨论落到可交付能力：跨任务泛化、长任务一致性、工具可靠性、权限控制、验证与经济性。路线图以当前失败样本和业务收益驱动，明确阶段目标、退出条件和人工接管。

历史与未来判断可作讨论题，不应替代上线能力、团队执行和风险管理的核心考核。

### 白话版答案

愿景可以讨论，计划必须能验证、能交付。

### 高级追问与评分点

老板要求半年内做“通用 Agent”，如何拆成三个可验收阶段，并定义何时停止投入？
