Q5: 什么是 Function Calling？它的工作原理是什么？

专业版答案

Function Calling 将模型的调用意图编码为结构化参数，应用或工具执行服务负责实际执行。应保留调用 ID，将每份结果匹配回对应请求，并允许一轮零个、一个或多个调用。

执行链路是：解析 → schema 校验 → 服务端身份与资源授权 → 业务约束 → 必要审批 → 执行 → 持久记录 → observation。结构化输出约束格式，不保证业务正确、授权成立或外部操作成功。流式参数必须完整组装并验证后才执行。

OpenAI 的 Responses 与 Chat Completions 使用不同消息结构；不能混用 function_call_output/call_id 和聊天工具消息格式。自建抽象消息需要适配器转换。参见 官方 Function calling。

白话版答案

模型填一张调用申请单，系统检查并执行，再把结果告诉模型。

高级追问与评分点

一轮三个调用只有两个完成时，如何关联结果、取消剩余任务并保持可恢复状态？

Q6: 如何处理 Function Calling 的失败情况？

专业版答案

错误返回使用稳定类别，区别“能否重试”与“是否允许执行”。

错误 处理
schema/参数错误 返回可修复字段信息，限制修复次数
授权拒绝 停止动作，不允许换工具绕过
业务拒绝 解释原因或转入合法替代流程
限流/暂时故障 有界退避、deadline、并发抑制
写操作超时 标记结果未知，查单或同业务幂等键恢复
模型协议错误 明确失败并记录适配器上下文

错误可带 code、retryable、operation_id、commit_state 和脱敏说明。重复调用检测用于发现停滞，不能替代写操作幂等；有进度的只读轮询不应被简单误杀。

白话版答案

先看错在哪一层；“请求超时”不等于对方没收到。

高级追问与评分点

解释 call ID、attempt ID、operation ID、幂等键各自的生命周期。
