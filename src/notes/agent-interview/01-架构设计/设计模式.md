# Agent 面试专题：架构设计 · 设计模式

> 校订：2026-09-21。面向高级工程师、架构与技术负责人。保留专题 Q 编号；与主题库 Q 编号分开使用。

## Q4: 常见的 Agent 架构模式有哪些？

### 专业版答案

先确定业务不变量，再选编排模式。

| 模式 | 适用条件 | 主要代价 |
|---|---|---|
| 固定工作流 + 模型节点 | 步骤稳定，只有抽取或分类不确定 | 开放任务覆盖有限 |
| 单 Agent 工具循环 | 路径依赖观察结果 | 步数和结束条件不稳定 |
| 计划—执行—重规划 | 长任务可拆成可验收里程碑 | 计划失效与状态同步 |
| 管理者调用专家 | 子任务可独立验收或隔离上下文 | 通信、整合与总预算 |
| Handoff | 需要转移当前交互责任 | 交接状态、权限与返回责任 |
| 生成—验证—修复 | 有独立验证器 | 验证成本和错误反馈 |

设计时说明谁拥有任务状态、谁批准副作用、谁判定完成。角色数不是架构质量指标。

### 白话版答案

按任务需要选择流程，每多一层就要说明它解决了什么问题。

### 高级追问与评分点

同一需求给出两个可行方案，比较故障面、研发成本和上线证据；不要只画多个角色框。
