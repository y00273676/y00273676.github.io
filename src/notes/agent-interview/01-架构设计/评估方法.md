# Agent 面试专题：架构设计 · 评估方法

> 校订：2026-09-21。面向高级工程师、架构与技术负责人。保留专题 Q 编号；与主题库 Q 编号分开使用。

## Q34: 如何评估 Agent 的性能和质量？

### 专业版答案

先定义可验证的业务结果，再分层评测：结果正确性、工具轨迹与约束、系统可靠性、成本延迟、安全与用户体验。必要时检查数据库或产物的真实状态，不能只看模型宣称“完成”。

评测集按任务类型、难度、租户、长短任务和失败风险分层，包含拒答、澄清、撤权、工具异常与恢复。固定环境快照和版本，记录每任务多次运行结果、样本量与不确定性。使用确定性校验、人工标注及校准后的 judge；安全关键事件单独报告，不能被总分平均掉。

轨迹允许多条合法路径；不应强迫模型模仿唯一工具序列。公开榜单用于了解能力边界，发布门槛必须来自自己的业务样本。

### 白话版答案

既看事情是否真办成，也看过程有没有越权、花了多少钱、能否稳定复现。

### 高级追问与评分点

100 个任务每个跑 5 次，如何汇总？报告任务级分布及重复试验相关性，不能把 500 次当作完全独立样本。
