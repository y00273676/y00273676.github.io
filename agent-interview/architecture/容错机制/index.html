Q17: 如何设计 Agent 的容错机制？

校订：2026-09-21。面向高级工程师、架构与技术负责人。保留专题 Q 编号；与主题库 Q 编号分开使用。

Q17: 如何设计 Agent 的容错机制？

专业版答案

将失败分为参数错误、授权拒绝、业务拒绝、暂时故障、提交结果未知、模型输出异常和预算耗尽。

  • 可恢复读请求可在 deadline 内退避重试，尊重 Retry-After，并控制重试放大。
  • 写请求超时可能已提交。先按业务操作 ID 查询；只有服务端幂等契约成立才重试。
  • 权限拒绝应停止该动作或请求合法授权，不能换工具绕过。
  • checkpoint 保存执行状态；外部副作用使用操作账本、幂等键与对账机制。
  • 降级须保留业务约束，例如退款执行失败只能转人工，不能编造成功。

补偿是新的业务操作，可能失败；恢复旧 checkpoint 不会撤销已发出的邮件或付款。

白话版答案

先弄清楚失败意味着什么，尤其要分清“没做成”和“不知道是否做成”。

高级追问与评分点

在外部付款成功、本地落库前杀进程。要求画出恢复流程并指出无法保证原子性的边界。
