Q20: 如何设计生产可用的 Coding Agent？

校订：2026-09-21。面向高级工程师、架构与技术负责人。保留专题 Q 编号；与主题库 Q 编号分开使用。

Q20: 如何设计生产可用的 Coding Agent？

专业版答案

让需求、仓库上下文、执行环境、补丁和验收形成闭环。读取项目约定、符号/依赖和测试，先复现问题，再修改、构建、测试并审查 diff。成功应由可观察的行为与产物证明。

使用独立 worktree/工作目录和受限凭据，明确网络、文件写入、依赖安装与发布权限。仓库文件、issue、依赖输出可能含注入，不能提升为运行时高权限指令。容器不自动解决宿主挂载和供应链风险。

长任务持久化计划、证据、当前 commit、补丁、测试结果和未决问题；恢复时检查环境是否变化。测试通过仍可能改错需求或偷改测试，需独立验收与人工 review。

负责人还应评估审查时间、逃逸缺陷、返工率和变更周期，不仅统计生成代码量。

白话版答案

从需求到可验证补丁，每一步都要留证据，权限和发布另有明确边界。
