Q54: Agent 如何动态生成工具 (Tool Generation)？

专业版答案

动态生成工具通常是生成脚本、组合现有 API 或产出候选工具定义。生成文本与获得执行权限是两个阶段。

先在隔离环境验证输入输出契约、依赖来源和测试；限制文件、网络、CPU、内存及执行时间；凭据按任务最小范围提供。候选通过评审、版本化登记后才可进入持久工具库。不能直接 exec 模型字符串并继承主进程权限。

Docker 只是隔离方案的一部分：挂载宿主目录、Docker socket、云凭据或过宽网络都会破坏隔离目标。应按威胁模型选择容器、强化沙箱或虚拟机。

白话版答案

它可以写一个新工具，但写出来不等于能立刻在生产环境运行。

高级追问与评分点

生成脚本需要访问内网数据库时，如何提供窄权限接口，而不是下发数据库管理员密码？

Q55: 工具调用的安全性如何保障？

专业版答案

安全检查在可信执行边界实现：真实主体、资源归属、动作范围、当前权限、额度和审批。工具定义与返回文本均可能来自不可信第三方，不能因接入协议标准化就信任内容。

敏感操作审批绑定动作摘要与规范化参数哈希、操作 ID、资源版本、有效期；执行前重验。运行环境限制网络出口与文件访问，凭据不进入模型上下文。审计记录谁授权、实际做了什么、结果是否已确认。

测试包括参数篡改、撤权、跨租户、描述注入、超时重放和组合外传：读取工具与发送工具单独合法，组合后仍可能违规。

白话版答案

既检查每个工具能不能用，也检查连起来之后会不会把数据送错地方。

高级追问与评分点

用户批准导出后撤销权限，排队任务还能执行吗？说明身份、审批和资源版本重验位置。

Q56: 记忆系统如何实现记忆压缩与摘要 (Summarization)？

专业版答案

压缩分成稳定约束、执行状态、证据引用和可摘要对话。稳定约束包括权限、用户限制、验收标准和预算，必须保存在权威结构化状态中；不能只存在于模型自由摘要里。

工具调用和结果成对保留，未完成调用不可丢。已完成大结果外置为带版本引用；保留当前结论、反证、未决事项和下一步。摘要需记录来源和版本，失败时退回上一个可信状态。

验证压缩前后约束遵循率、任务完成率、引用可恢复性，而不只看压缩比例。本题保留原路径与编号，记忆专题见 记忆架构。

白话版答案

交接笔记可以精简，但不能丢掉承诺、限制和已经做过的操作。

高级追问与评分点

审批凭证能否放进摘要？高分答案要求由服务端独立存储和验证。

Q57: ToT 与 ReAct 分别改变了什么？今天还需要手写思维树吗？

专业版答案

ReAct 强调动作与观察交替；ToT 强调生成多个候选状态并搜索、评估和剪枝。二者并非互斥，也不等于模型内部推理机制。

显式搜索适合有可验证状态、可比较候选和预算约束的任务。必须计算分支膨胀、评估器误差和环境执行成本；外部副作用不能为了搜索而多次真实执行。先在模拟器、只读环境或候选产物上验证。

现代推理模型可能已提供有效的内部搜索，但不保证替代任务级规划。是否增加树搜索，应与单 Agent、同预算多次采样和确定性求解器对照。

白话版答案

一个边做边看，一个多想几条路再比较；多想的成本和判断标准都要算。

高级追问与评分点

没有可靠候选评分器时，搜索更深为何可能更差？

Q58: Reflection (反思) 机制在 Agent 中的作用是什么？

专业版答案

Reflection 是依据反馈检查并修正结果的控制策略。有效反馈可以来自测试、静态分析、数据库状态、检索证据或人工意见。同一模型无新信息地反复检查，可能保留共同错误或把正确答案改错。

设置明确 rubric、修复轮数、总预算和最佳已验证版本；按错误类别触发修复，不对所有任务强制多一轮。记录每轮修复是否引入回归。

上线前做消融：不反思、仅自检、外部验证后修复，在相同总预算下比较成功率和成本。

白话版答案

有证据地改错才有价值，反复问自己“对不对”不保证变好。

高级追问与评分点

验证器误报时如何防止循环修复？要求保留基线、设置停止条件并支持升级人工。
