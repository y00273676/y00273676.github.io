> 校订：2026-09-21。面向高级工程师、架构与技术负责人。保留专题 Q 编号；与主题库 Q 编号分开使用。

## Q26: 如何设计一个好的 Agent 工具？

### 专业版答案

工具应表达明确业务能力，声明输入、输出、错误、权限、幂等和一致性契约。例如 `get_refund_quote(order_id)` 与 `submit_refund(operation_id, quote_version)`，比一个任意 SQL 或 shell 工具更容易约束。

服务端身份不由模型填写。金额使用最小货币单位整数或 Decimal；跨字段约束和订单实时可退金额在业务服务校验。只读、可逆写与不可逆写分开，返回真实提交状态和可查询的操作 ID。

返回结果保留来源、数据版本、分页信息与截断标记；大产物使用带权限的引用。描述中说明什么时候调用、必要前置条件及容易混淆的相邻工具。

### 白话版答案

接口要让模型容易选对，也让服务器容易检查；不要把后台所有能力一次交出去。

### 高级追问与评分点

评审一个 `execute(action, payload)` 万能工具：如何拆分，同时避免过度细碎导致调用爆炸？
